## Главные решения

1. **Токен — это доля в SPV, а не квартира.** Юридическая сила токена зависит от документов SPV, и это требует юриста: документ прямо помечает юридические пункты как допущения.
2. **Стейблкоин вместо SOL**, но программа **не привязана к одному токену**: платёжный mint лежит в конфигурации, переводы идут через `transfer_checked`.
3. **Расширения Token-2022 выбираются до первого выпуска**: их нельзя добавить позже. Для вторичного рынка рекомендован `TransferHook`, в Capstone он не реализуется и честно указан как ограничение.
4. **ML-модуль v1 — прозрачный расчётный скоринг**, а не обученная модель: реальных данных об аренде у проекта нет, и выдавать синтетику за «прогноз» нечестно.

## Находка расчётной модели

При комиссии 1% с аренды платформе нужно **около 580 объектов**, чтобы окупить $36 000 в год затрат. Только разовая комиссия листинга (1,5%) даёт **24 листинга в год** на то же покрытие. Поэтому обе комиссии в Capstone настраиваемые (`rent_fee_bps`, `sale_fee_bps`). Все исходные числа модели — **иллюстративные допущения**, их нужно заменить реальными.

## Запуск модели

```bash
cd model
python3 -m unittest -v      # 12 тестов
python3 unit_economics.py   # таблица сценариев bear / base / bull
```

Нужен только Python 3, внешних зависимостей нет.

## Тесты модели

| Группа | Что проверяют |
|--------|---------------|
| Водопад доходов | Каждый доллар потенциальной аренды учтён: вакантность + расходы + управляющий + комиссия + доход инвестора = потенциальная аренда |
| | Известные значения базового сценария (6 147,90 USD инвестору) |
| | Порядок сценариев bear < base < bull |
| | Рост комиссии уменьшает доход инвестора ровно на ту же сумму |
| | Безубыточность — действительно **минимальное** число объектов |
| | Некорректные допущения отвергаются |
| Раздел выплат | `сумма выплат + пыль = внесённая сумма` на 500 случайных наборах, пыль < числа держателей |
| | Никто не получает больше точной доли |
