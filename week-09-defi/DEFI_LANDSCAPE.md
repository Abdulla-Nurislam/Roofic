# DeFi-ландшафт Solana: обзор протоколов для Roofic

Данные по APY и ценам взяты из публичных API на дату запуска скриптов (см. `src/yields.ts`) и меняются ежедневно.

## Карта протоколов

| Категория | Протокол | Что делает | Модель дохода | Ключевой риск | Нужен ли Roofic |
|-----------|----------|-----------|---------------|---------------|:---------------:|
| DEX-агрегатор | **Jupiter** | Ищет лучший маршрут обмена по десяткам пулов, собирает swap-транзакцию | Комиссии пулов идут LP; Jupiter зарабатывает на сопутствующих продуктах (perps, DCA и др.) | Зависимость от маршрутизации, MEV | ✅ конвертация SOL↔USDC |
| AMM / CLMM | **Raydium, Orca** | Пулы ликвидности (constant product, concentrated) | Комиссия свопа идёт LP | Impermanent loss | ⛔ не для казны (IL) |
| Лендинг | **Kamino, MarginFi, Save** | Депозиты и займы под залог, supply APY из процентов заёмщиков | Спред между borrow и supply APY | Ликвидационные каскады, bad debt | ✅ размещение USDC казны |
| Liquid staking | **Marinade (mSOL), Jito (JitoSOL)** | SOL → токен-квитанция, которая растёт в цене вместе со стейкинг-наградой | Награды валидаторов + MEV (Jito) | Риск валидаторов, депег | 🔶 опционально |
| Оракулы | **Pyth, Switchboard** | Цены в блокчейне | Платные обновления feed'ов | Устаревшая цена, манипуляция | ✅ цена SOL/USD в приложении |
| Стейблкоины | **USDC (Circle), PYUSD, USDT** | Токены, привязанные к USD | Эмитент зарабатывает на резервах | Депег, блокировка адресов эмитентом | ✅ расчёты в USDC |
| Perps | **Drift, Jupiter Perps** | Деривативы | Комиссии, funding | Высокий риск | ⛔ вне scope |

## Как работают ключевые механизмы

### Pyth — pull-оракул
Классический оракул пушит цену в блокчейн постоянно и за это платит. Pyth работает по **pull-модели**: цена подписана publishers → агрегирована → доступна через Hermes API → **кто-то постит её в аккаунт `PriceUpdateV2`** в той же транзакции, что и использует. Для популярных пар (SOL/USD, USDC/USD) Pyth сам обновляет «sponsored feeds» с фиксированными адресами.

Безопасное чтение (реализовано в `src/pyth.ts` и во frontend):

| Проверка | Защищает от |
|----------|-------------|
| `owner == Pyth Receiver` | Подмены оракула своим аккаунтом |
| `verification_level == Full` | Неподтверждённой Wormhole-подписи |
| `age < N сек` | Устаревшей цены (оракул «залип») |
| `conf / price < 2 %` | Рынок нестабилен, цена ненадёжна |
| использовать `price − conf` для залога | Завышенной оценки активов |

### Jupiter — агрегатор
1. `GET /swap/v1/quote` возвращает **маршрут** (какой % через какой пул), ожидаемый выход, `otherAmountThreshold` (минимум с учётом slippage), price impact.
2. `POST /swap/v1/swap` собирает **v0-транзакцию** с address lookup tables: ComputeBudget → создание ATA → wrap SOL → вызов Jupiter → unwrap.
3. Пользователь подписывает и отправляет транзакцию. **Slippage** защищает от sandwich-атак: если выход ниже порога, вся транзакция откатывается.

Jupiter работает только в mainnet, поэтому в курсе мы запрашиваем реальную котировку и разбираем транзакцию, но не отправляем её.

### Kamino — лендинг
Депозитор получает **cToken-квитанцию**, чей курс к базовому активу растёт по мере начисления процентов. Заёмщик вносит залог (LTV 0.8 = можно занять 80 % стоимости залога). Если стоимость залога падает ниже порога, любой может ликвидировать позицию и забрать бонус.

## Выводы для архитектуры
- **Аренда должна выплачиваться в стейблкоине.** SOL за период владения сильно меняется, а арендный доход по определению стабилен.
- **Не размещать казну в AMM-пулах.** Impermanent loss съедает доход, а лендинг USDC даёт 4–6 % без него.
- **Оракул — единственная внешняя зависимость в логике денег.** Поэтому любая on-chain проверка цены обязана включать все пять проверок выше.
